SUPABASE STORAGE SETUP

1. Create a Supabase project.
2. Open Storage and create a bucket named: feedback-photos
3. Set the bucket to Public only if visitor photos are intended to be publicly viewable after approval. Anyone with a public image URL can view it.
4. In supabase-config.js replace:
   - https://YOUR_PROJECT_ID.supabase.co
   - YOUR_SUPABASE_PUBLISHABLE_KEY
   with the values from your Supabase project settings.
5. Configure Storage policies before using the form. Supabase Storage blocks uploads unless policies permit them. Do not use a service_role/secret key in frontend code.
6. Upload feedback.html, feedback.js, firebase-config.js, supabase-config.js, and feedback.css to the same folder/site path.
7. Existing admin approval code should copy the approved record into publicFeedback and include photoUrl. This setup still uses Firestore for feedback records and Supabase for photo files.

IMPORTANT SECURITY NOTES
- Browser-side file checks can be bypassed; configure the bucket's maximum file size and allowed MIME types in Supabase too.
- An anonymous upload policy can be abused. For a public production website, use a server/Edge Function with rate limiting or another anti-abuse mechanism rather than allowing unrestricted anonymous uploads.
- Keep Firebase Firestore rules strict: visitors must not be able to read feedbackPrivate or approve/publish records themselves.
- Only use the Supabase publishable/anon key in the browser. Never expose a service_role/secret key.
